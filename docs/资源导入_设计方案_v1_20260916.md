# 统一资源导入 · 设计方案 v1（2026-09-16）

> 用户要的：「一个地方可以直接导入各种压缩包或者文件夹，软件负责识别格式，
> 认不出来的让用户自己选、然后软件自己归类，类似击杀图标那边便利的操作。
> 官网的资源更方便兼容，非官网的也能通过选择很好地兼容。」

## 0. 先说三件改变方向的事实

**① 这个页面已经有了，但普通用户看不见。**
`pages/audio_import_wizard_page.py`（710 行）注册为 `audio_import_wizard`「资源导入向导」，
落在侧栏「工具与系统」组 —— 但它在 `gui_widget.py:227` 的 `_expert_only_pages` 里，
**只有专家模式才显示**。所以这件事的第一刀不是"做一个页面"，是**把它放出来并补足能力**。

**② 官网除击杀图标外，根本没有格式规范。**
社区站 `spec.php:267-271` 逐字写着「音效、语音、闪光等分类目前没有目录规范，
压缩包里怎么放都行」。结构级校验（`includes/pack_validate.php:412-450`）**只对
`category_id = 7`（击杀图标）生效**。
⇒ **"让官网资源更方便兼容"不能靠"认出官网格式"——那个格式不存在。**
能做的只有两条：认**包的文件名**（下载名 = `资源标题.zip`，`api/resources.php:2461`），
或者让站端在包里塞一份清单（见第 6 节，要用户拍板）。

**③ 机器在原理上就分不清其中五类。**
`weapon_kill_sounds` / `weapon_kill_voices` / `switch_weapons` / `reload_sounds` / `gun_sounds`
**五类共用**「`<武器>/<风格>/*.音频`」两层结构，且 12 类音频共用同一套扩展名
（`.mp3/.wav/.ogg`，`core/resource_catalog.py:30-48`）。
⇒ 现在那套「认出来 / 认不出来」的二分**在原理上就不成立**，认不出是常态不是异常。
这正是用户凭直觉提出「让用户自己选」的原因，而设计要把这一层做成**主路径**，不是兜底补丁。

## 1. 现有链路的欠账（逐条已复核）

| 项 | 资源导入向导（现状） | 击杀图标（标杆） |
|---|---|---|
| 吃压缩包 | ❌ 只能选目录 | ✅ zip，三道护栏 |
| 识别依据 | 路径里必须出现 spec 目录名，否则 `path does not include a supported resource category root` | 等级别名表（含中文「一杀/爆头」）+ `style.json` |
| 线程 | ❌ **UI 线程同步 `shutil.copy2`**（`_run_import` 直调） | ✅ `KillIconImportTask` 后台线程 |
| 进度 / 取消 | ❌ 都没有 | ✅ 都有 |
| 报错 | `QMessageBox` 弹数字汇总 | 页内提示条 + **可撤销** |
| 已有的好东西 | 冲突检测、路径逃逸防护、dry-run、导入前配置快照 | zip-slip / 压缩炸弹 / 压缩比三道护栏 |

⭐ **两条线各有对方没有的东西**，合并的方向是「向导吃图标那条线的工程能力，
图标那条线吃向导的批量与冲突处理」。

## 2. 识别：三级漏斗，取代二分

**第一级 · 确定**（直接落盘，只报告不打断）
- 路径里带 spec 目录名 —— 现有规则原样保留。
- 包内有清单文件且写明类别 —— 把击杀图标的 `style.json` 推广成通用的 `cs2customizer_pack.json`。

**第二级 · 高置信猜测**（**默认选项预先选好**，用户只需扫一眼点确认）
- **包名词典**（最高杠杆的一条，因为它直接吃掉官网包）：
  下载名就是资源标题，而标题几乎总含品类词。建一张中文/英文/别名对照表
  （「击杀音效 / killsound / 击杀音」…），命中即预选。
- **结构特征**：`1~5.png + 同名 .json` ⇒ 击杀图标；`<名>/<名>/*.音频` ⇒ 缩到那五类。
- **内容特征**：音频时长分布、图片尺寸、文件数、有没有 1~5 编号。

**第三级 · 不确定**（用户选，但要选得省力）
- **按"同构的一坨"分组**，对着组选一次，不是对着文件选 N 次。
- 选择面板上**摆出证据**：「这 12 个文件都在 `AK47/` 下，共 3 个风格」——
  用户是凭这个判断的，光给一个下拉框他也不知道选什么。
- **选完就记住**：同样形状下次不再问（学习表落配置）。

## 3. 归类：这个功能真正的价值

用户选了类别之后，软件要把散装文件**摆成目标结构**——这是现在完全没有的能力。

> 例：丢进来一个文件夹，里面是 `AK47.wav / M4A1.wav / AWP.wav`，用户选「枪声替换」。
> 目标结构是 `gun_sounds/<武器>/<风格>/*.wav`。
> 软件应当认出文件名是武器名，问一句「这套风格叫什么」，
> 摆成 `gun_sounds/ak47/<风格名>/ak47.wav`。

每类一个**归类器**（placement rule）。三个已知的硬骨头：

| 类 | 特殊在哪 | 归类器要做的事 |
|---|---|---|
| `death` | **平铺文件**，不是风格目录（`audio/death/death1.mp3` 就是一个风格） | 风格名 = 文件名，别建目录 |
| `round_sounds` | 多一层**固定**子事件目录（8 个：start/action/win/lose/mvp/…） | 要问「这是哪个回合事件」 |
| `c4_sounds` | 三事件**共用一个风格目录**，靠**文件名关键词**区分 | 落盘前就要检查关键词，见下一节 |

## 4. 落盘前预检：导入成功 ≠ 能用

三个"装进去了但不会响"的已知陷阱：

- **c4**：三事件靠文件名含 `planted/defuse/exploded/下包/拆除/爆炸` 等关键词命中，
  `find_audio_by_tokens` 找不到就返回 None，**不回落、直接不响**。
- **击杀图标**：缺等级。
- **round_sounds**：8 个子事件缺哪个。

⇒ 预检在**落盘前**跑，把这些提前讲清楚。
仿击杀图标现有做法：**只提示、不拦**（`pack_validate` 同款口径）。

## 5. 工程（一条都不新发明，全部抄已验证的那条线）

- **后台线程 + 进度 + 取消**：照搬 `widgets/kill_icon_import_task.py` 的四信号模型。
- **zip 护栏**：复用 `core/kill_icon_pack.py` 的 `_iter_safe_members`
  （3200 条目 / 512MB / 压缩比 500 / 拒绝 `..` 与绝对路径），**提升为通用模块**。
  ⛔ 不许写第三套 —— 现在已有两套（桌面端 + 站端），且两边是**逐字镜像**关系。
- **报错**：页内提示条 + 撤销，不用 `QMessageBox`。
- **事务性**：解压到临时区 → 预检 → 落盘 → 失败整体回滚。现有的"导入前配置快照"保留。

**压缩格式的诚实边界**：Python 标准库只有 zip / tar。
RAR 与 7z **不支持**，但要**认出来并说人话**（「这是 RAR，请先解压后再拖进来」），
而不是报「不认识的文件」。站端也是这么做的（按文件头魔数识破改名的 RAR/7z）。

## 6. 要用户拍板的两件事

**① 要不要动站端？**
最省力的"官网完美兼容"其实在站端：下载时往 zip 里塞一份 `cs2customizer_pack.json`
（分类 id + 标题 + 站点资源 id）。**这些站端本来就知道**。
客户端见到它就直接落第一级"确定"，一次都不用问。
代价：要改 `api/resources.php` 的下载链路 + 存量包回填（站端已有 `pack_backfill.php` 的先例）。

**② 这个页面叫什么、摆在哪？**
现名 `audio_import_wizard`「资源导入向导」，但它要管的是全部 17 类（12 音频 + 5 视觉），
名字里的 `audio` 已经名不副实。建议改叫「资源导入」并**移出专家模式**。
⚠ 改页面 id 会牵动：侧栏、搜索索引、图标表、页面基线、`audio_event_text` 的原因字典。

## 7. 分期

| 期 | 做什么 | 判据 |
|---|---|---|
| 一 | 吃压缩包 + 后台线程 + 进度取消 + 通用 zip 护栏 | 护栏三条各一例；大包不卡 UI |
| 二 | 三级漏斗识别 + 包名词典 + 分组确认面板 | 五类同构包必须走到"问用户"；官网包名命中率 |
| 三 | 归类器（含 death / round / c4 三个特例）+ 落盘前预检 | 每类一个往返：散装进 → 摆好 → 页面能选到 |
| 四 | 移出专家模式 + 改名 + 旧入口收编 | 同步面：搜索索引、图标、基线、原因字典 |

⭐ 一期就能独立发布（它只是把现有向导变得不卡不炸），不必等三期做完。
