# 帆派助手后台静默自查常见失败处理手册 v1

## 1. 文档定位

本文档用于回答：

- 我后台静默自查时如果发现问题，第一时间应该怎么判断、怎么处理、怎么避免越修越乱？

它不是总规范，也不是页面矩阵，而是“故障处理手册”。

## 2. 使用原则

发现问题后，不要直接进入“边猜边改”模式。

标准顺序是：

1. 先分类
2. 再定位
3. 再决定是否立即修
4. 修完必须回归

绝不允许：

- 没定位清楚就大改
- 视觉问题顺手带业务重构
- 配置问题顺手改 5 个页面
- 交互问题没加回归就直接宣布解决

## 3. 问题分级

### 3.1 `P0 阻断级`

表现：

- 关键输入框无法输入
- 下拉为空
- 帮助面板打不开
- 页面明显裁切导致主操作不可达
- 配置回写失效
- 当前静默检查污染真实配置

处理原则：

- 立即停止“继续往下查更多页面”
- 先修这个问题
- 修完先复测本页，再继续总检查

### 3.2 `P1 高优先级`

表现：

- 状态条、摘要、action bar 不同步
- 帮助文案路径错误
- 关键提示语误导用户
- 窄宽度下主要控件严重拥挤

处理原则：

- 本轮应尽量修掉
- 修完补回归

### 3.3 `P2 一般问题`

表现：

- 文案略不顺
- 间距不协调
- 帮助面板个别段落偏长
- 次级页面空白感偏重

处理原则：

- 记录
- 视本轮范围决定是否修
- 不要为了它扩大到 unrelated 页面

## 4. 常见失败类型与处理方式

## 4.1 帮助面板相关

### 症状

- 问号按钮不存在
- 点击后面板不展开
- 展开后文字为空
- 文案有路径但与代码不一致

### 优先排查

1. 页面是否正确调用 `install_help_panel`
2. `PAGE_HELP_TEXTS` 是否有对应 key
3. key 是否拼写错误
4. 帮助文案是否在最近改动里被覆盖

### 处理动作

- 修映射或 key
- 修帮助文案
- 补帮助展开测试
- 重抓帮助展开图

### 复测最低要求

- `test_ui_help_panel_texts.py`
- `test_ui_form_and_help_interactions.py`

---

## 4.2 输入框不可用

### 症状

- 输入框不能输入
- 输入后立刻被清空
- validator 把合理输入也挡掉
- 输入后配置不更新

### 优先排查

1. 是否被设成 `readOnly`
2. `validator` 区间是否过窄
3. `textChanged` / `editingFinished` 是否接到了错误逻辑
4. 载入配置时是否把用户输入覆盖掉

### 处理动作

- 先确认是“不能输入”还是“输入后不生效”
- 只修本输入链路
- 补最小交互回归

### 复测最低要求

- 相关页面交互测试
- 本页离屏图

---

## 4.3 下拉框 / 单选项异常

### 症状

- 下拉为空
- 当前值不在选项中
- 切换后无联动
- 单选框显示和配置不一致

### 优先排查

1. 选项来源是否正确扫描
2. 默认值是否还能被识别
3. `currentTextChanged` / `currentIndexChanged` 是否还连着
4. 加载配置时是否找不到对应值

### 处理动作

- 修选项来源
- 修默认值兼容逻辑
- 修联动回调

### 复测最低要求

- 该页交互测试
- 相关专项测试

---

## 4.4 状态条 / 摘要 / action bar 不同步

### 症状

- 控件变了，但 badge 没变
- 摘要没跟着变
- action bar 文案还是旧状态

### 优先排查

1. 更新函数是否统一走一个入口
2. 某个控件变更后是否忘了调用同步函数
3. `load_settings()` 后是否补同步
4. 标签页切换时是否补同步

### 处理动作

- 尽量统一到一个同步函数
- 避免每个回调各写一套摘要逻辑

### 复测最低要求

- 页面状态条专项
- 至少 1 次真实交互触发

---

## 4.5 离屏视觉问题

### 症状

- 布局挤压
- 按钮遮挡
- 帮助展开后首屏塌掉
- 横向滚动条出现
- 页面过长、有效内容被压缩
- 离屏截图中文字变方块

### 优先排查

1. 是固定宽度控件过多，还是容器方向不对
2. 是帮助面板高度问题，还是正文布局问题
3. 是文案过长，还是 spacing / size policy 不合理
4. 是否只是 `offscreen` 字体回退，而不是页面文本本身丢失

### 处理动作

- 优先改布局方向、宽度策略、size policy
- 其次压缩文案
- 不要先去删功能
- 如果只是离屏中文字体方块，但文本断言正常、布局结构正常，则先记录为“环境字体回退风险”，不要直接当产品 bug

### 复测最低要求

- 同尺寸重抓图
- 至少看前后对比两张

---

## 4.6 配置回写问题

### 症状

- 改了控件，配置没变
- 当前显示变了，重开又没了
- 配置写到了错误字段

### 优先排查

1. 回调有没有真正触发
2. 是否调用了 `config.save_config()`
3. 配置 key 是否拼错
4. 载入逻辑是否又把它覆盖回旧值

### 处理动作

- 先最小修 key / 回调
- 再补逻辑测试

### 复测最低要求

- 交互测试
- 配置逻辑测试

---

## 4.7 静默性被破坏

### 症状

- 跳出文件夹
- 弹出真实消息框
- 真实声音播放
- 真实 `fanpai.cfg` / `autoexec.cfg` 被写入
- 真实配置被改

### 优先排查

1. 是否漏 stub / monkeypatch
2. 是否用了真实 `LOCALAPPDATA`
3. 是否直接调用了系统行为
4. 是否有页面在初始化或 `load_settings()` 过程中触发了 CFG 写出

### 处理动作

- 立刻停止当前检查
- 清理临时目录
- 核对真实配置与真实资源目录
- 核对真实 CS2 目录下的 `fanpai.cfg`、运行期 CFG 和 `autoexec.cfg` 是否被触碰
- 修正隔离方式后重来

### 这是硬阻断

这类问题默认按 `P0` 处理。

## 6. 不该做的事

### 6.1 为了修视觉问题，顺手改业务逻辑

禁止。

### 6.2 为了修一个页面，顺手把一整批页面结构重做

禁止。

### 6.3 还没确认根因，就把同步逻辑散落到每个回调里

禁止。

### 6.4 明明是静默检查失败，却继续在真实环境里硬跑

禁止。

---

## 7. 最终定义

以后我后台静默自查时，如果发现问题，默认先按这份手册分类和处理。

它的目的不是把流程变复杂，而是让我修问题时更稳、更克制，不把本来简单的问题修成新的问题。
