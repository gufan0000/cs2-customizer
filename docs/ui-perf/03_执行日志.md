## R0 · 立项与全面勘察 — 2026-08-07

### 做了什么

1. **全维度勘察**：10 路并行调查覆盖「启动与首屏 / 主线程卡顿源 / 渲染与动画 / 主题与样式系统 / 设计系统与现代化 / 页面级 UI 质量 / 易用性与便利性 / 资源内存与生命周期 / 实测证据与可观测性 / 历史文档与未竟事项」，产出 **113 条带代码锚点的发现**。
2. **对抗式验证**：对 41 条 P0/P1 逐条打开源码回查 —— 36 条核实、4 条降级、**1 条推翻**。
3. **实测基线**：解析 `%LOCALAPPDATA%\CS2Customizer\logs` 下 47 个真实日志（369 次会话 / 88 次有效启动 / 449 条卡顿记录），建立 R0 基线。
4. **建立体系**：本 `docs/ui-perf/` 目录 + `scripts/ui_perf_probe.py` 探针。

### 核心结论（三条）

1. **"微卡顿"的真身是启动期，不是使用中。** 449 次卡顿里 424 次（**94.4%**）在启动后 15 秒内。稳态使用几乎不卡。
   → 火力集中在 W2，别做全局撒胡椒面优化。

2. **页面静默预载与卡顿是严格 1:1 对应。** 每建一个页面 = 一次 150~640ms 主线程停顿，14 个页面排队 → 启动后 2.3~9.4 秒连续卡。驱动代码 `main_widget.py:1208`，源码注释已自认「单页构建本身要 200-500ms(主线程不可切)」。

3. **稳态期那 25 次卡顿，大部分其实是"关窗口冻 3 秒"。** `停止闪光进程` 在 21/38 次退出中触发慢步骤告警，中位 2.43s —— 子进程不响应优雅退出，只能等超时强杀。

### 意外发现（推翻了一个看似合理的方向）

有一条 P0 发现声称「建页时 `clear_all_styles` 无条件刷整棵子树，单页凭空多花 350ms」。验证员**实测推翻**：真实页面 622 个子控件里带样式表的仅 40 个，无条件版 19~22ms，加守卫版 20~27ms —— **守卫零收益**。

同时实测：`generate_stylesheet` 仅 **0.18ms / 42KB**。

> **结论：样式层不是性能瓶颈，后续不要再往这个方向查性能。** 已写进 [02_问题清单](02_问题清单.md) 末尾的"别再走回头路"表。

### 意外发现（好的那面）

这个项目的样式架构比预期好得多，勘察实测确认：QSS 正文 `#RRGGBB` 字面量 **0 个**、198 条规则 **0 条重复选择器**、全应用只有 45 处 `setStyleSheet`。**这是最值钱的资产，已写入红线文档保护起来。**

### ⚠️ UP-008 做了又回退（复核全量报告到齐后）

一度用"后台线程预热 GSI import"实现（那批 import 实测合计 1695ms，正是"窗口画出来了却冻 1.5 秒"的来源）。复核实测推翻，三条理由：

1. **把音频设备初始化搬到了后台守护线程。** `gsi_handler_kills.py:8` 是模块级 `audio_manager = get_runtime_audio_manager()`，顺着 `AudioManager.__init__:109` 直接 `pygame.mixer.init()`。对一个以音频为核心的软件，设备归属与回调线程亲和性的变化**不能在没有真机验证的情况下上线**。
2. 这批模块还会拉入 pygame/SDL，与 `window.show()` 首次渲染并发正是已记录的原生崩溃路径。
3. 复核实测 `show()` 之前只剩约 **80ms** 余量，join 超时兜底反而可能变成 5 秒静默冻结。

**正确改法是结构性的**：把 GSI 构造真正异步化，或让 `audio_manager` 惰性初始化——不是抢跑 import。已退回问题清单。

### 复核全量报告补修的另外两条严重项

- **空闲判据分不清「用户走开」和「用户切进 CS2 打比赛」。** 只看"多久没输入"会把这两种相反情形判成一样：用户 Alt-Tab 进游戏后本应用收不到任何输入、"看起来"很空闲，而那恰恰是最不该抢 CPU 的时刻。`is_idle` 现在要求**应用是前台**且距上次输入超阈值。
- **GSI 启动结果最长 15 秒才显示。** 状态条放宽到 15 秒后，"GSI 起没起来"（起不来 = 游戏内没有任何音效）也跟着延迟。已在异步回查后主动推一次刷新。

另修：`eventFilter` 去掉 try/except（它会被每一个 Qt 事件调用，含建页时成千上万次布局/绘制事件，实测带 try 明显更慢）；page_usage 改原子写盘（临时文件 + `os.replace`，原先被退出看门狗切断会留半截 JSON 导致「常用」分组清零）；`flush()` 先取消挂起 Timer。

### 对抗式复核（4 视角 × 独立审查）

复核结论均为"有条件通过"，共 21 条疑点，**修掉 12 条实质问题**。其中打中我自己的：

1. **日志清理曾是 import 副作用** —— `build_release.py` 生成 spec 时 `collect_submodules("core")` 会 import core 包并触发清理，**每跑一次打包就删光打包机的历史日志**，pytest 护栏在打包场景下不生效。已改为 `Logger.start_maintenance()` 显式入口。

4. **UP-004 静默杀死了「主题回调注册数」** —— 该埋点是 DEBUG 级，降级后恒为 0 且整段不打印，R0 唯一测到的回调泄漏证据（最大 12425 次注册）会静默消失。探针现在识别日志级别并显式标注"指标不可用"。

### 先量后改：离屏建页基准（新增 `scripts/bench_page_build.py`）

为了不启动真实软件（会打扰前台：准心窗口/全局热键/音频设备/GSI 端口）也能测建页耗时，写了离屏基准。它给出了本轮最重要的定性结论：

| 条件 | kill_sound 建页耗时 |
|---|---|
| 热态、无全局 QSS | **37ms** |

> **单页构建慢的主因是 Qt 样式解析**（每页 630~670 个子控件各自解析），不是业务代码。
> 想靠"分帧构建"或"优化控件代码"把它压下去不现实。

### 做了什么

这一轮的复核价值比 R1 更高——我自己写的代码里有真回归：

1. **【阻断】UP-014 把两个功能悄悄关掉了。** `viewmodel` / `voice_output` 的构造函数正是「视角自动切换线程」与「音板全局热键注册」的**唯一启动点**。把它们从预载池删掉，等于这两个已开启的功能在用户手动打开页面前完全不生效。
   → 改为单列「功能激活队列」：必定会建完（不受空闲门控约束），但仍对切页让路。

2. **【严重】`ensure_page_loaded` 改了返回语义，三条老调用链没跟上。** 都是「先 pop 出队、再忽略返回值」。其中 `_build_next_then_connect` 会让 flash/magnifier/utility 建不成 → `_connect_gsi_now` 的守卫跳过 handler 连接 → **自定闪光/开镜放大/道具瞄点整个会话静默失效**。触发条件是"用户在启动头几秒切了一次页"——恰恰是 R2 自己认定的高发场景。

### R3：退出冻结的根因找到了，而且是必然发生

R0 日志说「点 X 冻 3 秒」，元凶是 `退出步骤[停止闪光进程]偏慢`。这次读代码找到了根因：

> `FlashEffectProcess.shutdown()` 跑在**命令线程**上，却在那里调 `pygame.quit()`。
> 主循环此时很可能正卡在 `display.flip()` / `blit` 中途，SDL 显示被并发拆掉，
> 子进程于是挂住不退，父进程只能等 `join(timeout=2.0)` 超时后 `terminate()`。

为了排除完整 App 里的时序干扰，写了隔离实验 `scripts/bench_flash_stop.py`（只起停子进程本身）：

| | stop 耗时 |
|---|---|
| 修复前 | 中位 **2019ms**，**8/8 次全部卡满 2 秒超时** |
| 修复后 | 中位 **79ms** |

2019ms 正好等于父进程的 join 超时值——**子进程每次都没能自己退出**。这不是偶发竞态，是必然发生的；只是在完整 App 里因页面构建时序不同，有时表现不出来（这解释了为什么 R2 的两次 40 秒跑测没触发，而我手动跑的 230 秒那次触发了）。

**修法**：`shutdown()` 只置标志；`pygame.quit()` 交给主循环退出后自己做（那是唯一能保证"此刻不会再有渲染调用"的位置）；父进程 `stop_process` 把"发关闭命令"提到"join 监控线程"之前（原先顺序反了，那 2 秒里子进程根本不知道要退）。

顺带做了 UP-012：9 处每帧新建全屏 Surface（14.7MB × 120fps ≈ 1.7GB/s churn）改为缓存复用。

### 追查：R4 把 QSS 撑大了 7.4%，这要不要紧？

真机跑测（n=3）报了两条劣化：`启动→全就绪 +318ms`、`flash 建页 +79ms`。
而 QSS 确实从 **41929 → 45021 字符（+7.4%）**（禁用态规则组 + searchHit + chip 两态）。
R2 已经证明建页开销由 Qt 样式解析主导，所以"改 QSS 让建页变慢"是个**可信的**假设，
不能当噪声打发。

于是给 `bench_page_build.py` 加了 `--with-qss` 档（默认档不挂全局 QSS，
正是 R2 说的 35ms 那一档，**测不出 QSS 改动的代价**），做了对照实验：

| | QSS 长度 | 18 页建页中位合计 |
|---|---|---|
| R4 第 1 次 | 45021 | 1439ms |
| R4 第 2 次（同代码重复跑） | 45021 | **1481ms** |
| R3 源码（`git checkout e8bf4eb --`） | 41929 | 1436ms |

**同一份代码重复跑的差异就有 ±3%（42ms）**，而 R4 与 R3 的差异是 3ms。
结论：**QSS 长 7.4% 对建页耗时没有可测量的影响**——Qt 的样式表只解析一次，
每个控件的解析成本取决于**有多少条规则命中它**，不是样式表总长度；
而新加的 `:disabled` / `[searchHit]` 规则在常态下根本不命中。

所以真机那两条劣化是 n=3 的噪声，不是 R4 引入的。
（顺带确认了 R2 的结论：挂 QSS 1439ms vs 不挂 214ms —— 样式解析占建页开销 **85%**。）

### 发现并修掉了探针自己的一个 bug

`--compare` 报出「内存峰值(中位): 733.0 → 0.0 (-733.0MB) 改善 ✅」。
但同一份报告下面写着「内存指标暂无数据」——**两句话自相矛盾**。

根因：`summarize()` 在无样本时把内存指标写成 `0` 而不是 `None`，
`_cmp` 又用 `o or 0, n or 0` 兜底，于是"这次没采到样本"被算成"降到了 0MB"。
内存埋点每 60s 采一次，而这次会话只有 50s——**必然一个样本都没有**。

**凭空捏造的改善比没有数字更糟**：它会让人误以为某轮优化解决了内存问题。
已在**产出侧**修（无样本写 `None`），并让 `--compare` 在一侧缺数时明说"无法比对"。

### UP-035 是本轮的重头：它修的是数据安全，不是刷新体验

原状：点「应用预设」→ 成功提示 → 切回一个**之前打开过**的页面 → 控件还显示旧值
（它只在构造时读过一次配置）→ 用户随手动一下滑块，`_on_xxx_changed` 就拿控件里的
**旧值** `save_config()`，把刚应用的整套预设悄悄改回去。恢复快照同理：
回滚功能在已访问过的页面上直接失效。

改法：新增 `core/config_reload_bus.py`（模块级回调表），
`apply_bundle()` 和 `restore_snapshot()` 两个写入点广播，`gui_widget` 订阅。

三个设计决定，每个都有具体理由：

1. **总线放 core 而不是让 core 直接调 UI**：core 是被 UI 依赖的下层，
   反过来 import 会成环；而且预设/快照/地图规则在无 GUI 场景（测试、CLI）也要能跑。
2. **必须经 Signal 回主线程**：`core/presets/map_rules.py` 的按地图自动切预设是
   GSI 事件驱动的、跑在**后台线程**上，在那儿直接碰 Qt 控件会崩。
3. **订阅者异常必须被隔离**：配置此刻已经落盘了，把异常抛回调用方只会让用户
   以为"应用预设失败"，而它其实成功了——那比界面没刷新糟得多。

**动手前先验了前提**：计划里写着"页面已有 `_loading` 守卫，重入安全"。
grep 发现 `crosshair_page` 和 `flash_page` **零守卫痕迹**，所以没敢信，
写了个探针：建页 → 监视 `save_config` → 调 `load_settings()`。
8 个安全页全部 0 次回写，前提成立才动手。
（要是会回写，这个方案就等于把数据安全洞换了个位置。）

### 踩到的坑

1. **`getattr(obj, name, default)` 的 default 不吞 property 内部的异常**，只挡
   AttributeError。`preview_feedback` 的 docstring 写着"任何异常都吞掉"，
   但取 `page.action_bar` 那一步没包起来——**测试抓到了自己的实现没兑现承诺**。
2. **PySide6 的 `findChildren` 不接受类型元组**（PyQt 可以）。改成
   `findChildren(QWidget)` + isinstance 过滤，顺带保住了控件树顺序，
   于是"第一个命中"天然是页面上最靠前的那一项。
3. **`isVisible()` 要求整个窗口已显示**。用它做过滤，在"切页后还没画出来"的
   一拍里会把所有控件都当成不可见、全部落空。改用 `isVisibleTo(page)`：
   只看它到 page 这一段有没有被 hide()，正好排掉折叠的帮助面板，又不依赖窗口状态。
   **这个 bug 是靠跑验证脚本发现的，单元测试没覆盖到那条路径。**
4. **向上找"行"没设层数上限**，控件直接挂在滚动内容上时会一路走到顶，
   把整块内容区当成一行高亮——那还不如不定位。限到两级。
5. **bash heredoc 里的 `

   已改用 Write 工具落新文件、只用脚本做精确替换。

### 本轮最重要的一件事：我自己的第一版改动被自己的度量否掉了

2. `gui_widget.__init__` 构造 `CS2CustomizerAuthClient`（其 `__init__` 直接 `make_session()`）→ session 改惰性

### 为什么用惰性代理而不是「把 import 挪进用到它的函数」

`crosshair_animation` 用的是 threading 不是子进程，pygame 必须能在主进程加载，
只能推迟不能移走。而 `pygame.` 散在该文件十几个方法里——逐个改 import 漏掉一处
就是运行期 AttributeError。**用崩溃换启动速度是赔本买卖**，所以新写
`core/utils/lazy_module.py`：首次属性访问时导入真模块并把自己从调用方全局里换掉，
漏掉的那处照常工作，只是多付一次 import。

配套两处细节：
- 退出清理改走 `peek_runtime_audio_manager()`。走惰性 property 的话，
  本次运行从没碰过音频时，「清理」这一步会**为了 cleanup 反而把整套 pygame 拉起来**。
  peek 先查 `sys.modules`，只看已存在的实例（可能是 GSI 线程建的，不限本窗口）。
- `CS2CustomizerAuthClient.session` 补 setter——注入假 session 是既有用法，
  不能因为加惰性就堵死（5 个既有用例就是这么炸的）。

### UP-048 的定性要反过来写

原记录：「设计 token 只活在 theme_manager 里，页面引用 0 次」。

## R8d · 焦点顺序（UP-077）—— 52 处报告，2 处真缺陷

### 判据错了，不是页面错了

### 唯一的真缺陷

于是进音乐页按 Tab，**第一站是底部动作条的「刷新列表」**。

排版毫无异常，坏的只有键盘顺序，所以它一直没被看见。
kill_sound 页是先 add 内容再建动作条，所以它一直是对的（实测 0 处错位）。
修法就是把那一行提前。改完用几何对拍验过：**116 个控件逐控件坐标完全一致**，
只动了焦点链。

### 判据重写

- **阅读序递归**：块（卡片 / 动作条 / **滚动区** / **页签**）之间按行排，块内部再递归。
- **「同行」按矩形垂直重叠判**，不用固定像素容差。固定容差有两个毛病：
  边界脆（voice_output 主音量行与模式行正好差 24px，被并成一行再按 x 排就反了），
  且**不随字号缩放**——1.25 档下行距变大，同一个 24px 会从"同行"变"跨行"。
- **错位数报「最少要挪动几个控件」**（n − 最长上升子序列），不报逐位差异。
  逐位那个数字不但没用，还消耗信任：照着 16 去找的人会找不到 16 个东西。

覆盖 5 → **11 页**，全部为 0。CI 从**警告级改阻断级**。

## R8b-E · 翻准心默认值 —— 「只能在真屏幕上看」这个口径是错的

R8b-D 把默认值定在 `pygame`，理由写的是「置顶 / 点击穿透 / 缩放屏居中
**只能在真屏幕上看**，而那会打扰前台」。用户问「怎么回归，你做呢」，
一追下去发现**那个口径是我自己划得太保守了**：这三样绝大部分能程序化验，
而且**比人眼严**。

| 原以为要人眼看 | 实际怎么验的 | 实测 |
|---|---|---|
| 「看着像在正中」 | `GetWindowRect` 量物理像素 | 边长 100×100，中心偏差 **(+0.0, +0.0)** |
| 「点得动下面的东西」 | `WindowFromPoint` 打屏幕正中 | 命中的不是准心句柄 |
| 「没抢走焦点」 | `GetForegroundWindow` 三点采样 | 全程稳定在同一个窗口 |
| 「盖得住游戏」 | 造一个**非置顶**全屏窗口比 Z 序 | 准心 Z=**28** vs 假游戏 Z=**70** |

`scripts/verify_r8b_live.py`（新增）在屏幕正中真显示准心约 1 秒，共 **22 项全过**：
五个扩展样式、几何、穿透、Z 序、不抢焦点、
4 样式 × 6 色 × 9 动画 × 10 联动逐帧有像素、
隐藏+显示 **4.2ms**（老实现重建一次曾要 916ms）、静态准心定时器真的停下。

另外用 `scripts/live_run.py` 跑了**整个软件**（给它加了 `--set` 配置覆盖）：
日志确认走 Qt 渲染器、准心自动显示、**零 ERROR**、优雅退出码 0；
再跑一次 `pygame` 对照组，两边 `native_crash.log` 内容**逐字一致**。

真正只能靠人眼的只剩**观感**（11 个联动与老版的视觉差异），属主观项，不阻塞。
默认值已翻到 `qt`，回退仍是一行。

### 顺手记的 UP-088

A/B 对照暴露出一条与本轮无关的既有问题：每次启动稳定写一条
`0x8001010d`（`RPC_E_CANTCALLOUT_ININPUTSYNCCALL`）到 `native_crash.log`，

**但它每次启动都写一条，会把真正的崩溃淹掉**——这才是要修的理由。

### 踩坑记录（本轮三条判据全是自己写错）

1. **「静态准心不跑定时器」报 FAIL** —— 上一段刚触发过击杀联动、0.8s 没走完，
   此时定时器本来就该在跑。**判据缺了前提，不是产品有缺陷。**
   改成先等联动过期再断言，并顺带把「它会自己停」也证了。
2. **「假游戏拿到焦点」报 FAIL** —— Windows 不允许后台进程 `SetForegroundWindow`，
   从控制台进程里 `activateWindow()` 根本推不动前台，断言的**前提**不成立。
   改成验真正该验的：**准心自己不是前台窗口**（置顶 ≠ 抢焦点，这两件事常被混为一谈）。
3. **「默认值必须是 qt」报 FAIL** —— 判据构造 `Config()` 去读属性，
   而 `Config.__init__` **会加载配置文件**，测试隔离目录里存着上一轮跑出来的
   `"pygame"`。**它测的是持久化的值，不是默认值**；此前"通过"只是碰巧两者相同。
   改成 AST 读源码里的赋值，并验过改回 `pygame` 立刻变红。

**一条判据第一次跑红，先查判据的前提成不成立**——本轮三次全是这个。

### 踩到的坑（六个，每个都值钱）

1. **判据报红先查前提，第 N 次应验。** `preset_center` 一上来报「焦点错位 2 处」。
   实测两行复选框 y 区间 `[273,290)` 与 `[298,315)`，**间隙 +8px 根本不重叠**。
   真因：工作台三列并排，而那三列是**裸的 QVBoxLayout**（没有承载它们的控件），
   判据看不见列的存在，中间列一个 34px 高的下拉框把两行**桥接**成了一行。
   改成按子布局分组后假阳性消失——这是 R8d 对「并排卡片」定论的同一件事，
   只是这次并排的是裸布局。

2. **判据要对准缺陷本身，不是对准一个相关的量。**
   `audio_import_wizard` 的换向判据第一版用「五个按钮 `minimumSizeHint()` 合计 vs 可用宽」，
   想着自带字号缩放不变性。它**判过头了**：在 1200×800（可用约 946px）就换成竖排，

   **padding 被压缩 ≠ 文字被裁**。页面指纹当场逮住（16 个控件挪位），改回实测锚点的常数阈值。

3. **`setTabOrder` 必须写在控件拿到父控件之后。** 写在 `addLayout` 之前时，
   reparent 会按插入顺序**重建焦点链**，把结果冲掉——第一版就写在前面，判据照旧报红。
   这是「判据跑红先查前提」的反面：**前提成立时，红就是真的**。

4. **回退验证逮出我自己 4 条判据是假绿的**（13 条里 4 条）。四条各不相同：
   ① `assert "--compact" in src` —— 把开关改名成 `--compact-DISABLED`，
   子串照样命中（**别用子串判断**，第 6 次）；

5. **我自己的注释又骗了我自己的判据。** UP-006 的结构判据比

   **同一个教训在本项目是第 5 次**，第 2 次栽在自己写的注释上。改成比 AST 节点行号。

6. **bash heredoc + 正则批量改中文引号 = 把脚本自己改坏。** 写登记册补丁时
