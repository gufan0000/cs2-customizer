| R8b 的第三个发现（落地阶段） | **手写的接口名单一定会漏——漏的恰好是你没想到的那几个。** 迁准心时先手写了一份「新旧实现要对齐的方法」名单，看着挺全；改成按**真实调用点** AST 扫之后，多出六个：`pages/magnifier_page.py:1568-1574` 会把准心当前设置整套 `getattr` 读回来存档（进放大镜改成红色小点，退出还原），而老实现那六项是**公开实例属性**、新实现原本藏在 `_state` 里 —— 接线后放大镜退出会把准心还原成**别的样子，且一个错都不报**。判据在接线前就抓住了它。<br>判据自己还错了两次：第一版用 `hasattr(类, 名字)`，被 `is_visible` 判红（那是**实例**属性不是类属性）；改成扫 AST 后只扫点号访问，`overlay_win` 又漏了（用的是 `getattr` 字符串访问）。**新判据第一次跑绿，先怀疑判据。** |
| 重构安全网 | 动结构前先跑 `python scripts/page_fingerprint.py --save <基线>`，改完 `--compare`。它把页面整棵控件树（类型/名字/文案/几何/启用态）拍成指纹。**先验证它跑两次完全一致再用**——不稳定的指纹只会制造假差异。UP-057 就是靠它证明"四页合并后逐控件零变化"的。 |
| **判据的判据（R8a 最贵的教训）** | **新加一条守门判据时，必须先证明它能抓到已知缺陷、且把被测代码回退后它会变红。** R8a 一轮里犯了三次「判据锚在错的东西上」：① 对比度判据自己调产品函数现算前景色再判 AA（同义反复，改坏也全绿）；② 纵向判据用 `findChildren` 找滚动区（不含自身）+ 取树序第一个匹配，实际只覆盖 **5/54** 个测量范围；③ 子进程唤醒判据挂在一个首次显示后永真的状态上。三处都不是逻辑写错，全是锚点错。 |

| R5 的关键发现 | ⚠ **offscreen 平台一个真实字体都没有**（`QFontDatabase.families()` 返回空），中文 `horizontalAdvance` 返回 0 或假值。任何依赖文字宽度的判据在 offscreen 下都会给出**假绿**——这个坑从 2026-06-12 起就在审计脚本里，从没被记录。<br>现在审计默认走**原生平台 + `WA_DontShowOnScreen`**：拿真实度量，但窗口永不映射到屏幕、不打扰前台。换上真字体后立刻抓出 2 条真缺陷。 |

### 2. 动手前必须知道的三件事

1. **"微卡顿"的真身是启动期**——449 次实测卡顿里 424 次（94.4%）发生在启动后 15 秒内，稳态使用几乎不卡。**别做全局撒胡椒面优化。**
2. **样式层要分两件事看**（R2/R4 实测细化，别只记住半句）：
   - **生成 QSS 文本**不是瓶颈——`generate_stylesheet` 实测 0.18ms，`clear_all_styles` 19~27ms。"样式导致卡顿"的原始推断就是被这两个数推翻的。**别再去优化这两处。**
   - **把 QSS 应用到控件树**才是大头——挂全局 QSS 时 18 页建页合计 1439ms，不挂只要 214ms（**占 85%**）。整表 `setStyleSheet` 在 15 页已加载时要 **370ms**。
   - 但**QSS 变长 ≠ 变慢**：R4 让 QSS 涨了 7.4%，建页耗时零变化。Qt 的成本在"多少条规则命中这个控件"，不在样式表总长度。放心加**常态不命中**的规则（`:disabled`、属性选择器）。
3. **有红线**——玻璃拟态 / 发光边框 / 重动效 / 重做导航 / 藏按钮，这些在 2026-03 已被否决。动手前读 [04_设计约束与红线](04_设计约束与红线.md)。

# 三、R0 勘察的三条核心结论

### 1. "微卡顿"= 启动后头 10 秒，不是用着用着变卡

449 次实测卡顿的分布：

| 时段 | 次数 | 占比 |
|---|---|---|
| **启动期（≤15s）** | **424** | **94.4%** |
| 稳态期（>15s） | 25 | 5.6% |

而那 25 次稳态卡顿里，大部分还是**点 X 关窗口时冻 3 秒**（`停止闪光进程` 在 21/38 次退出中超时强杀，中位 2.43s）。

**真正的使用中卡顿，接近于零。** 这是个好消息 —— 靶子小而明确。

### 2. 页面预载与卡顿严格 1:1

```
[懒加载] 创建页面: kill_sound  →  [卡顿] 主线程停顿 639ms
[懒加载] 创建页面: kill_voice  →  [卡顿] 主线程停顿 450ms
[懒加载] 创建页面: switch_weapon → [卡顿] 主线程停顿 502ms
```

14 个页面排队，每个 150~640ms，全在主线程。源码注释已自认这件事。
这就是 `UP-005` —— 本专项的头号靶子。

### 3. 底子比预想的好，别改坏

勘察实测确认的既有优势（完整清单见 [04](04_设计约束与红线.md) 第三节）：

- QSS 正文 `#RRGGBB` 字面量 **0 个**，颜色 100% 来自 token
- 198 条 QSS 规则、**0 条重复选择器**
- 全应用只有 45 处 `setStyleSheet`
- `PageActionBar` 在 **26/28 页**统一落地
- 音频 LRU 上限、`deque(maxlen)`、图标缓存 500 上限 —— **不是典型的内存泄漏型项目**

> 这个项目的问题**不是"不够现代"，是同一套好规则只落实了一半**。方向是把已有的规则铺满，不是换一套新规则。
