## 三、这个专项真正学到的东西

技术结论会过期，方法会留下来。按「被应验的次数」排序：

### 1. 「全绿」要先问分母 —— 应验 3 次，一次比一次贵

| 编号 | 分母的谎 | 藏了什么 |
|---|---|---|
| `UP-071` | 纵向维度**根本没有判据**，报告照样全绿 | `about` 页整页无滚动区，内容 1091px 压进 750px |
| `UP-096` | 排版审计默认跳过 5 页，报告写「22 页全绿」读起来像全覆盖 | `UP-094` / `UP-095`，其中 flash 页**版面塌掉、文字重叠不可读** |
| `UP-100`/`UP-101` | 尺寸轴（紧凑模式从没跑过）与页面轴（焦点巡检 11/27） | 三类排版缺陷 + 一处 Tab 顺序缺陷 |

**固化到工具里**：三个审计现在都**每次无条件打印覆盖面**，
并由 `tests/test_audit_coverage_r11.py` 盯着——覆盖面只许增不许减。

### 2. 判断「调用 / 构造」永远走 AST，不要看文本 —— 应验 **6 次**

六次形态各不相同：`"name" in src` 被 import 行骗；逐行正则被**注释**骗；
「同时有文件名和 `Popen`」误报一个把文件名列在表里的脚本；
`assert "--compact" in src` 被 `--compact-DISABLED` **子串命中**；
比 `src.index()` 先后被自己的 **docstring** 骗；
`ast.walk` 扫全函数被**嵌套函数**里的同名赋值骗。

**正解统一是**：AST 找真正的 `ast.Call`，必要时连实参、连行号、连作用域一起匹配。

### 3. 会假绿的判据比没有判据更坏 —— 所以有回退验证台

`scripts/revert_verify.py` 现有 **35 个断点**，每个都是真实发生过的缺陷：
逐条改坏产品代码 → 跑对应判据 → 确认变红 → 还原并校验。

**R11 这一轮它就逮出我自己 4 条新判据是假绿的**（13 条里 4 条，32%）。
没有这道工序，那 4 条会一直挂在那里，看着像有门禁。

### 4. 判据第一次跑红，先查判据的前提成不成立

`UP-077` 报 52 处焦点错位，**50 处是判据自己的假阳性**；
R11 的 `preset_center` 报 2 处，也是假阳性（两行间隙 +8px 根本不重叠，
是并排的**裸布局**把它们桥接成了一行）。

**但它的反面同样成立**：前提成立时，红就是真的。
R11 的 `setTabOrder` 写错位置，判据照旧报红——那次红是对的。

### 5. 先量再改，能省掉整轮工作量

- `UP-045`「页面外边距三套值散落全站 170+ 处」→ 量窗口坐标后真相是 **19/21 页早已对齐，只需改两页**。
- `UP-013`「spawn 带 3 次重试」→ 拆账后真相是重试**一次 sleep 都不睡**，
  394ms 里 359ms 是**一次同步 import**。
- `UP-058`「1349 行 / 73%」→ 复量是 **1541 行 / 68%**。

### 6. 审计出的数字读不出严重度，该拍图就拍图

`UP-095` 报「纵向超出 279px」，听着像「滚一下就好」；
实拍才看到 Qt 满足不了最小高时**把控件压扁**，卡片标题与正文字形重叠成一团。
`UP-100` 的「超出 71px」同理——实际是滚动区被挤成 **62px 的舷窗**。

### 7. 登记册自己会过期 —— 描述已错 **16 次**

R10 开工前校准查出三处失真（`UP-082` 早修好了、`UP-081` 指错页签、
`UP-047` 标着已修复但一半没做）；R11 又查出四处
（`UP-013` 归因错、`UP-058` 数字过期、`UP-008` 锚点过期、
外加 **R10 自己漏了收工协议第 1 条**，四条已修的状态没回填）。

**照旧表开工会白做一遍。每轮开工前先校准登记册。**

### 8. 自造的指标先校准再用

R9-D 用「抹掉标识符后的 AST 结构相似度」判断能不能抽基类，`_init_ui` 只得 59%，
差点判定抽不动——原始 diff 一看是 **75 行里 72 行完全相同**。

同类：查编码损坏时先用「乱码高频字」启发式，把 pypinyin 词库里的
「民淳俗厚」当成乱码。最后只留「含 Unicode 私有区字符」这一个**零误报**信号。

| `scripts/page_fingerprint.py` | 22 页整棵控件树，重构安全网 | 手动（动结构前后必跑） |
| `scripts/live_run.py` | 隔离跑真软件 + 真实退出链路 | 手动 |

### 三条硬约束（踩过就别再踩）

1. **隔离有三个出口**：`CS2C_CONFIG_DIR`、`CS2C_LOG_DIR`、
   以及**存在配置里的 `config.csgo_dir`**。第三个有两条路：进程内建页的审计脚本走
   `scripts/_audit_sandbox.sandbox_external_writes()`；起子进程跑整个软件的走
   `live_run.py` 的沙箱游戏目录（`--real-game-dir` 是正门）。
   没堵的时候用户真实 CS2 目录会被写 **5 个文件**。
2. **别在 offscreen 平台下判文字**：本机 offscreen 一个真实字体都没有，
   文案截断结论是**假绿**（`UP-068` 误导过一个多月）。CI 里用 `--require-fonts` 兜底。
3. **打包链路**：PyArmor 只混淆根目录 `.py`；hiddenimports 只扫种子文件。

`UP-066`（已推翻，缺陷不存在）｜

**「不做」不等于「不管」**：每条都有一个能变红的数字，不是一句话。

## 五、最后两条：已拍板不修（2026-08-09）

R11 结项时曾把这两条交回用户拍板。**复查「谁在读它」之后结论很清楚：
`docs/tutorial/` 是一条废弃的平行管线，不值得修。** 四条依据：

1. **不进安装包** —— `build_tools/build_release.py` 的 datas 里没有它。
2. **零调用者** —— `scripts/build_tutorial_pdf.py` 与 `scripts/build_user_guide_pdf.py`
   在全仓（CI / 构建脚本 / bat / 文档）**一处引用都没有**。
3. **出货手册走的是另一条线** —— `scripts/build_cs2customizer_manual_v2.py` 读 `docs/manual/`，
   那边 **0 个文件损坏**，`output/` 里已生成的 PDF 都是它出的。
4. **内容本身已过期** —— 锚在 **2.1.0 / 快照 2026-03-03**，当前版本 2.2.1。

修它三重不划算：**文字不可逆恢复、修好也是过期内容、修好也没人读。**

**处置：文件原样保留，不修不删。**
`docs/tutorial/assets/` 下 **205 张截图是好的**（图片没有编码问题），
将来若要重建教程可直接复用。判据继续把范围钉死：
`docs/tutorial/` 之外一个损坏文件都不许有、目录内只许减不许增——
放着不会扩散；将来真要清掉，判据只会更绿。

下面两小节保留原始描述，供将来重建教程时参考：

### `UP-099` —— `docs/tutorial/` 教程内容库编码损坏（42 个文件）

`manifest.yaml` 加 `steps/` 下 41 个 `.md`，中文全是乱码。
成因是 UTF-8 被当 GBK 解码后又存回 UTF-8，与 `UP-091` 是**同一次基线导入事故**。
**自动还原不成立**（带私有区字符的部分不可逆）。

可选处置：从教程站线上内容反向恢复 / 重写 / 弃用该目录。

### `UP-091` —— 两个连语法都不过的脚本

`scripts/bootstrap_tutorial_content.py` 与 `scripts/capture_web_tutorial_screenshots.py`，
同一次事故，**全仓无任何引用**，不在 CI 里。320 行中文里 287 行带不可逆损坏。

可选处置：修内容 / 删文件 / 留着。

> 判据已经把范围钉死：`docs/tutorial/` 之外**一个损坏文件都不许有**，
> 该目录内的数量**只许减不许增**。所以放着不处理也不会扩散。

## 六、专项之后怎么维护

1. **改了布局 / 控件尺寸** → 跑排版审计**两档**（默认 + `--compact`）。
2. **改了主题色 / QSS** → 跑对比度审计。
3. **动了页面结构** → 改之前 `page_fingerprint.py --save`，改完 `--compare`；
   **控件身份多重集有增减 = 弄丢东西了**，几何变化才看设计意图。
4. **加了新判据** → 必须往 `revert_verify.py` 里加一个断点并跑通。
   **没验过「回退即变红」的判据，默认当它是假绿的。**
5. **接手前先读** [README](README.md) 的「新会话 30 秒接手」，
   并**先校准登记册**——它已经错过 16 次。
