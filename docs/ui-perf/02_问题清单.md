### UP-005 是本专项的头号靶子（铁证）

日志里页面创建与卡顿是**严格 1:1 对应**：

```
13:16:06  [懒加载] 创建页面: kill_sound
13:16:07  [卡顿] 主线程停顿 639ms (启动后 2.3s)
13:16:07  [懒加载] 创建页面: kill_voice
13:16:07  [卡顿] 主线程停顿 450ms (启动后 3.0s)
13:16:08  [懒加载] 创建页面: switch_weapon
13:16:08  [卡顿] 主线程停顿 502ms (启动后 3.9s)
...  持续到启动后 9.4s
```

源码里已经承认了这件事（`main_widget.py:1215` 注释原文）：

> `2.2.0 卡顿治理:间隔 50→200ms——单页构建本身要 200-500ms(主线程不可切)`

**已试过但不够的办法**：把调度间隔从 50ms 拉到 200ms。这只是把卡顿之间的缝隙拉宽，单次停顿仍是 200~640ms。

**建议的三层解法（按投入排序）**：
1. **让预载让路于用户**：用户一有输入就暂停预载队列，空闲再续。现在是无条件 200ms 往下推，用户正在操作时照样插一页进来。
2. **让单页构建变快**：先查清 200-600ms 到底花在哪（W1 的埋点做完就能测）。注意 —— 曾有一条"`clear_all_styles` 单页多花 350ms"的推断**已被实测推翻**（实际仅 19~27ms），别再往这个方向查。
3. **分帧构建**：把单页构造拆成多个 chunk 跨帧执行。工作量最大，最后考虑。
