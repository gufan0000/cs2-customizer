# P1 性能预算（2026-11-02）

预算是同机、同工装的退化门禁。先量现状，再冻结上限；不把当前达标误写成产品优化已完成。

## 口径与定数规则

- 改动前旧版 `python scripts/health_table.py` 三轮中位：启动 515.5 ms，show 后 RSS 107.5 MiB，空闲 10 秒后 RSS 143.9 MiB，线程 22，模块总数/本仓 300/79；无 `.build/release-*/dist`。
- 新增读数在预算正式冻结前用 `python scripts/health_table.py` 采三轮；下表“基线”均来自这一次。Python 3.13、Windows、本机源码、干净配置；各子进程顺序执行，未并跑测试。
- 数值上限 = max(现状中位 × 1.20, 规划目标)。规划 §一给出堵循环后的 0~0.5% CPU，§二/P3 给出首开 ≤200 ms；CPU 用 0.5、首开各页及汇总用 200 作较宽下限。启动/RSS 的规划参考值为 463 ms、109/142 MiB，本次 ×1.2 更宽。没有规划目标的项只取现状 +20%。计数向上取整，其余向上取到小数三位；等于上限通过。
- **绝对宽限下限（主会话验收时加）**：首轮复测 28 项超限，其中 27 项是 4~17 ms 的再开和每秒 4 次的上下文切换，这个量级上 20% 小于抖动，一跑就红的预算没有用。所以上限再取 max(上面那个数, 下限)：逐页首开 300 ms、逐页再开 30 ms、再开中位 20 ms、再开最大 50 ms、上下文切换 15 次/秒、CPU 1.0%。这些下限守的是「用户感觉得到的退化」，不守毫秒级抖动；下表「预算上限」列是加下限之前的数，以 `budget.json` 为准。
- **逐页首开再放一档（同上）**：加下限后单跑两次各红 4 项，都是音效几页的首开，单跑在 350~480 ms 之间跳 ±30%。逐页首开上限改成 max(300, 1.25 × max(三轮基线, 这两次单跑))，只算一次（原来卡在 300 下限的页按 300/1.2 回推基线，落在 312.5）。复核单跑一次 rc=0。这几页正是 P3 要优化的，预算守的是别再变慢。
- 不自动重算预算。优化后若要收紧，必须先重测，再审阅修改 JSON；`--check` 不写预算。
- 旧启动、RSS、线程、模块和安装包构成口径保留；`--idle` 仍只控制旧版 RSS 读数时刻。新增 CPU 测量须启动满 max(75s, --idle)，覆盖启动回调及随后线程退出；早期试量在 17~47 秒区间仍发生线程变化，故延长等待；原始含负切换率的数据整批作废；每种窗口状态再等 2 秒，随后用精确定时器量至少 10 秒，按实际经过秒数计算。
- 状态窗口统一 1280×800、默认 basic 页：显示、最小化、隐藏（没有托盘图标时进托盘只做存几何 + `hide()`，体检表直接 `hide()`，不伸手进私有方法，X1 契约）。全程 offscreen + WA_DontShowOnScreen，不创建原生托盘图标，不占全局热键/真实音频设备，不启动 CS2。托盘项只覆盖窗口隐藏逻辑。
- 单核 CPU = (user+system CPU 秒增量)/实际墙钟秒×100；不除逻辑核数。主进程 CPU 起点在采样枚举结束后读取，终点在下一次枚举之前读取，排除工装自身枚举进程/线程的 CPU 成本。上下文切换/秒取主进程 voluntary+involuntary 增量，是调度计数代理，不是硬件唤醒次数。
- 进程树 CPU/RSS 合计主进程及递归子进程；RSS 是区间结束快照，不是峰值，共享页可能重复计入。首尾进程或线程集合变化、计数倒退则丢弃该窗口；每个状态最多尝试三次，仍不稳定就整轮失败；区间内短命进程/线程未持续追踪。Windows 的存活线程计数来源见 [psutil 实现](https://github.com/giampaolo/psutil/blob/master/psutil/arch/windows/proc.c)。离屏不启动闪光子进程，进程树读数也是下界，不能替代真局验收。
- 逐页实走 ensure_page_loaded + show_page(animated=False, force=True) + processEvents；28 页各首开/再开一次。basic 已在启动同步构建，其首开栏只量导航成本，构建成本在启动项；其余 27 页要求首开前均未加载。再开前先离开目标页。包含布局/样式/当次事件处理，不等待后续异步网络/媒体任务完成；无动画。
- 汇总是“每轮的逐页中位/最大值，再取三轮中位”，逐页数也是三轮中位，二者的最大值可能不同。所有逐页数各有独立预算，避免汇总掩盖单页退化。
- 安装包构成原逻辑保留。本机没有构建产物，无法冻结包体预算；本次 --check 不宣称包体达标。游戏、真实素材库、闪光子进程及打包版都未验收。
