## 1. A5 · 日志脱敏

### 1.1 验证敏感字段被替换

1. 启动应用：`python main_widget.py`（或双击 exe）
2. 让它正常加载（看到主窗口即可）
3. 打开日志文件：`%LOCALAPPDATA%\FanTool\logs\fanpai_<今天>.log`
4. 搜索下列字符串应**全部找不到**：
   - `C:\Users\<你的 Windows 用户名>\`（应为 `C:\Users\***\`）
   - 你的完整 Steam ID（若登录过）
5. 搜索 `***` 应能找到多处命中（尤其是启动那几行 "日志文件" 路径）

### 1.2 验证正常日志不被误伤

1. 打开主窗口，点几下页面，产生一些日志
2. 日志里**仍能看到**：
   - 中文消息（如 "加载风格", "快捷键按下"）
   - 时间戳（`2026-04-19 13:45:23`）
   - 行号（`[GSIHandlerKills:123]`）
   - 武器名 / 回合编号 / 击杀计数等

**通过条件**：敏感字段消失 + 正常日志可读。

## 2. D2 · 单实例互斥锁

### 2.1 验证双开被阻断

1. 启动一次应用，让主窗口出现
2. **再双击启动一次**（或再跑一次 `python main_widget.py`）
3. 期望：**第二次启动弹窗**显示"帆派助手已在运行中..."，点确定后退出
4. 第一次实例应该正常继续运行

### 2.2 验证强杀后能恢复

1. 任务管理器 → 结束第一个实例进程（选择"结束任务"）
2. 等待约 30 秒
3. 再启动应用 → 应能正常启动（stale lock 已自动清理）

**通过条件**：双开被阻，强杀后 30s 内能恢复。

4. 重启 → 改动保留（这是 closeEvent + atexit 双保险）

**通过条件**：两种关闭方式都保住改动。

## 4. B3 · 资源迁移标志

### 4.1 验证标志文件生成

1. 启动应用一次，让它完成初始化（可看到主窗口即可）
2. 检查 `%LOCALAPPDATA%\FanTool\.resources_migrated` 文件应存在
3. 用文本编辑器打开，应有 JSON 内容：
   ```json
   {"schema": 1, "version": "2.1.1", "timestamp": "20260419_134523"}
   ```

### 4.2 验证二次启动加速

1. 关闭应用
2. 打开日志文件，定位到最后一次启动的时间戳
3. 再启动应用
4. 日志中应出现：`资源迁移标志命中，跳过完整扫描`
5. 从启动到看到主窗口的时间应明显缩短（主观感觉 1 秒内）

### 4.3 验证标志损坏能自恢复

1. 关闭应用
2. 用文本编辑器把 `.resources_migrated` 改成 `{corrupted}`（非合法 JSON）
3. 启动应用
4. 期望：正常启动（不崩），日志看不到"命中"字样（走完整流程），文件被重新写成合法 JSON

**通过条件**：标志文件机制正确触发且对损坏鲁棒。

## 5. D1 · 信号兼容的优雅退出

### 5.1 验证 Ctrl+C

1. **从命令行启动**（不是双击 exe）：
   ```
   cd <仓库根>
   python main_widget.py
   ```
2. 等主窗口出现
3. 切回命令行窗口，**Ctrl+C**
4. 期望在日志里看到：
   - `收到信号 2，请求优雅关闭`
   - `关闭窗口`（closeEvent 被触发的日志）
   - 各模块 cleanup 日志（audio / crosshair / flash 等）

### 5.2 验证 SIGTERM（可选）

Windows 下 SIGTERM 需要用 `taskkill` 不带 `/f`：
```
taskkill /PID <进程ID>
```

期望行为同 Ctrl+C。

**通过条件**：信号能触发完整 closeEvent，资源被正常清理。

## 6. B4 · GSI 回调异常堆栈

### 6.1 被动验证（推荐）

让应用正常跑一局 CS2 → 如果任何 callback 抛异常，日志里应**同时有**：
- `击杀回调错误: <消息>` / `调用地图更新回调失败: <消息>`
- **完整 Traceback**（`File "...", line N, in ...`）

### 6.2 主动制造异常（技术向）

开发调试模式下，可以在某个 gsi_handler 的回调注册点故意注入会抛异常的回调，观察日志是否带堆栈。**一般场景不需要这么做**。

**通过条件**：异常发生时日志有堆栈，不再只有单行 error。
