# 帆派助手 UI 打磨蓝图 v1

## 1. 目标

这份蓝图用于指导 `cfg-fanpai` 后续的 UI 打磨方向，目标不是推翻现有界面重做，而是在不影响易用性、不破坏现有功能、不引入额外 bug 的前提下，把帆派助手从“好用的工具”提升到“成熟、有品牌感的桌面产品”。

核心目标只有四个：

- 更专业
- 更统一
- 更有品牌感
- 更不打扰使用

最终希望达到的效果是：

- 老用户几乎不需要重新学习
- 新用户第一眼更容易理解重点功能
- 界面更像成熟桌面产品，而不是功能堆叠页
- 所有高频页面在视觉节奏上统一、克制、耐看


## 2. 设计原则

后续所有 UI 改动必须服从下面这些原则。

### 2.1 功能优先

- 不为了“更好看”而改变核心功能路径
- 不把常用按钮藏深
- 不为了极简牺牲可发现性
- 不降低文字对比度
- 不把高频入口改得难找

### 2.2 低风险优先

- 先改样式层，再改布局层，最后才考虑结构层
- 优先做全局样式统一，不轻易大改业务页面结构
- 每次只做一小批页面或一小类组件，避免大爆改
- 任何页面改造都不能同时混入业务逻辑重构

### 2.3 保持桌面软件感

- 不做过度网页化设计
- 不做大面积浮夸渐变、玻璃拟态、发光边框
- 不做看起来“炫”但影响阅读和操作的动效
- 保持工具型桌面软件的稳定、清晰、专业感

### 2.4 品牌感来自系统，而不是装饰

- 品牌识别主要来自颜色、层级、状态语言、标题风格
- 不依赖大图背景、花纹、复杂装饰制造“高级感”
- 所有页面都应该看起来像同一个产品，而不是一组独立页面


## 3. 当前版本的评价

基于当前 `2.1.1` 版本，现状可以总结为：

- 信息架构是清楚的，左侧导航 + 顶部状态 + 右侧内容区这套结构是成立的
- 已经脱离了传统工具软件的土味风格，整体不丑
- 深色主基调符合产品定位，账号入口也已经开始具备产品感
- 但品牌辨识度仍偏弱，视觉层级略平，页面之间的一致性还不够强

当前问题不是“丑”，而是“还不够精”。

这意味着后续优化不需要推倒重来，而应该通过设计系统收敛、页面节奏优化和局部精修来完成提升。


## 4. 未来风格定位

建议把帆派助手未来的视觉定位定义为：

`冷静、专业、轻电竞感、强桌面工具属性`

具体落地应该表现为：

- 深色主界面继续保留
- 使用单一主强调色构建品牌识别
- 在线、成功、错误、警告使用明确状态色，不与品牌色混用
- 控件视觉统一、留白更稳、标题和内容层级更清楚
- 页面第一屏就能表达当前页面的核心用途

不建议走的方向：

- 不建议变成炫技型电竞皮肤
- 不建议变成网页后台风
- 不建议用过多霓虹色或高饱和配色
- 不建议做过强动画和频繁动态效果


## 5. 视觉系统目标

这一部分是未来 UI 打磨的根基，优先级最高。

### 5.1 色彩系统

目标：

- 1 个主品牌色
- 4 个状态色
- 4 层背景层级
- 3 层文字层级

建议规则：

- 品牌色只用于焦点、主按钮、选中态、关键标题强调
- 绿色只用于在线/成功
- 黄色只用于离线缓存/提醒
- 红色只用于错误/危险操作
- 蓝色或青色只用于信息提示，不与主品牌色冲突

落地目标文件：

- `theme_manager.py`
- `ui_modern_styles.py`
- `ui_design_system.py`

### 5.2 字体与层级

目标：

- 页面主标题更明确
- 区块标题有统一规格
- 提示文案更轻但不虚
- 数据类信息和说明类信息一眼可分

建议层级：

- 页面标题：22px 左右，明确重量
- 区块标题：16px 左右，统一强度
- 正文信息：13-14px
- 辅助提示：12px

### 5.3 间距与卡片

目标：

- 页面内边距统一
- 卡片间距统一
- 卡片标题、正文、按钮区的间距统一
- 不同页面不要出现明显不一致的密度

建议基线：

- 页面左右边距：24
- 卡片内边距：16-18
- 卡片间距：16
- 标题与正文距离：8-12
- 按钮区与内容区距离：12-16

### 5.4 圆角与边框

目标：

- 按钮、输入框、卡片、badge 的圆角成体系
- 不同控件不要各用各的圆角值

建议：

- 小控件：6
- 常规控件：8
- 大卡片：12
- 状态 badge：10-12


## 6. 核心区域改造目标

### 6.1 左侧导航栏

现状：

- 导航结构清楚
- 选中态可识别
- 分组逻辑合理

问题：

- 品牌感不够强
- 分组标题、当前项、普通项之间层级还能再拉开
- 版本区域偏功能性，视觉完成度一般

未来目标：

- 让导航有更稳定的“桌面应用骨架感”
- 让选中态更精致，但不更花
- 让分组更易扫读
- 顶部品牌区更完整，但不占太多空间

建议做法：

- 统一导航项高度、缩进、字体和 hover 反馈
- 分组标题更轻、更整齐，不抢内容
- 当前选中项保留左侧强调线，但增加更细腻的背景层级
- 品牌区增加更稳定的标题/副标题节奏

### 6.2 顶部栏

现状：

- 顶部栏已经具备基础产品感
- 右上角账号入口表现不错

问题：

- 顶部栏的全局职责还不够清晰
- 页面标题、账号状态、模式切换在视觉上仍可以更统一

未来目标：

- 让顶部栏成为真正的全局状态栏
- 左边表达当前位置，右边表达全局状态和快捷操作
- 减少重复信息，让重点更集中

建议做法：

- 左侧只保留当前页面名称
- 右侧保留账号状态、模式切换、未来更新入口
- 控件高度统一到同一基线
- 顶部栏阴影和底部分隔更克制

### 6.3 内容卡片区

现状：

- 大多数页面已经采用卡片分区
- 功能归类基本成立

问题：

- 卡片视觉语言虽然统一了一部分，但节奏还不够稳定
- 有些页面偏松，有些页面偏满
- 第一屏重点功能不一定足够突出

未来目标：

- 所有页面都遵守统一卡片规则
- 第一屏只承载最重要内容
- 辅助说明尽量靠近相关功能，而不是到处散落

建议做法：

- 卡片标题区、内容区、操作区统一结构
- 高优先级动作放在第一块卡片
- 次级说明收进 hint 样式，不抢主内容
- 数据展示页避免大片空白

### 6.4 表单与按钮

现状：

- 主按钮、次按钮已经有区分
- 输入框整体可用

问题：

- 不同页面按钮风格统一度还可以继续提高
- 表单页在“焦点”和“完成状态”反馈上还不够精致

未来目标：

- 所有主按钮有一致的优先级表达
- 次按钮不抢主按钮
- 输入框 focus、hover、disabled 反馈明确统一

建议做法：

- 主按钮只保留一种主要视觉语言
- 次按钮尽量使用描边或弱背景
- 危险操作统一红色体系
- 表单的提示、错误、成功文案统一样式

### 6.5 状态系统

现状：

- 在线、成功、错误这类状态已经开始体现

问题：

- 同一个状态在不同页面里表达方式可能不完全一样
- 状态 badge、字段文字、顶部按钮有时会出现重复信息

未来目标：

- 统一所有状态色和状态文案规则
- 状态优先级明确，避免一个页面同时重复表达相同状态

建议做法：

- 主状态只保留一个最显眼入口
- 次状态通过字段或 hint 补充
- Toast、badge、字段、按钮的状态语言统一


## 7. 页面优先级

后续打磨不建议全量同步开工，应该按用户频率和视觉影响排序。

### 第一优先级

- 基础设置
- 账号中心
- 准心设置
- 关于软件
- 顶部栏
- 左侧导航栏

### 第二优先级

- 音乐播放
- 语音输出
- 高级设置
- 击杀音效
- 击杀语音

### 第三优先级

- 音频任务面板
- 音频体检
- 配置快照
- 预设中心
- 其他低频或偏工具型页面


## 8. 推荐实施顺序

### 阶段 A：设计系统收敛

目标：

- 不改业务逻辑
- 不改页面结构
- 只统一基础 token 和全局样式

主要动作：

- 整理颜色系统
- 整理圆角、边距、字号
- 整理主按钮、次按钮、危险按钮规则
- 整理输入框、标签、提示文字规则

产出：

- 一套稳定的全局视觉基线

风险：

- 很低

### 阶段 B：全局框架精修

目标：

- 精修导航栏、顶部栏、内容容器
- 不改路由，不改业务逻辑

主要动作：

- 左侧导航统一节奏
- 顶部栏统一布局和状态优先级
- 内容区卡片统一

产出：

- 全应用视觉骨架统一

风险：

- 低

### 阶段 C：高频页面精修

目标：

- 只打磨高频页面
- 通过少量页面提升整体体感

主要动作：

- 基础设置首页重整第一屏
- 账号中心更像正式产品页
- 准心设置和音乐页做视觉节奏优化
- 关于页补足品牌信息

产出：

- 用户感知最明显的一轮升级

风险：

- 中低

### 阶段 D：低频页面收尾

目标：

- 补齐统一性
- 减少“主页面很精、边缘页面很旧”的割裂感

主要动作：

- 工具型页面逐页套用统一规范
- 补齐空状态、异常状态、加载状态

风险：

- 中低

### 阶段 E：细节增强

目标：

- 只加轻量反馈，不影响性能和稳定性

主要动作：

- 微动效统一
- Toast 优化
- hover/focus/pressed 反馈统一
- 滚动区和分隔元素优化

风险：

- 中


## 9. 明确禁止项

为了保证易用性和稳定性，下面这些事情不应该做。

- 不重做整套导航结构
- 不打散现有页面组织关系
- 不为了极简把按钮和文案藏起来
- 不引入复杂视觉特效库
- 不把动画做重
- 不在同一轮 UI 改动里顺手改业务逻辑
- 不在没有测试的情况下批量替换大量页面布局
- 不用“好看”为理由去破坏高频操作路径


## 10. 风险控制方案

后续如果按这份蓝图实施，必须配套下面的风险控制流程。

### 10.1 代码层原则

- UI 改动与功能改动分开提交
- 优先改样式表、设计 token、局部容器
- 少改页面内部业务信号和数据流

### 10.2 每轮改动的最小验证

- `python -m py_compile`
- 离屏实例化关键页面
- 主窗口基本显示 smoke test
- 人工打开 exe 看导航、顶部栏、主页面是否正常

### 10.3 每轮打磨后的人工回归页

- 基础设置
- 账号中心
- 准心设置
- 音乐播放
- 关于软件
- 更新与启动链路

### 10.4 打包与回滚

- 每个阶段结束后重新打包
- 保留一个可直接打开的发布包
- 同时保留源码快照和项目完整备份


## 11. 验收标准

一轮 UI 打磨是否成功，不看“是不是更花”，看下面这些标准。

### 视觉层

- 同类控件样式一致
- 页面密度更均衡
- 标题、正文、提示、状态层级清晰
- 第一屏重点更明确

### 易用层

- 老用户能快速找到原有功能
- 页面扫描速度更快
- 主操作入口更明显
- 状态信息更少重复、更好理解

### 稳定层

- 不出现页面无法打开
- 不出现布局错位、文本遮挡、按钮点不到
- 不影响账号、更新、音频、准心等现有功能
- 打包版本运行正常


## 12. 首批可立即落地的 10 条优化

如果后续开始做，优先建议从下面 10 条入手。

1. 统一全局颜色 token，明确品牌色与状态色边界
2. 统一主按钮、次按钮、危险按钮三套规则
3. 统一输入框高度、圆角、focus 态
4. 统一卡片 padding、标题区、按钮区节奏
5. 精修左侧导航的分组标题和选中态
6. 精修顶部栏，让账号、标题、模式切换基线统一
7. 压缩部分页面第一屏空白，提高专业感
8. 统一状态 badge 样式和文案规则
9. 补齐空状态、异常状态、加载状态的统一表达
10. 对高频页面做截图级前后对比，确保“更精致但不更难用”


## 13. 最终结论

帆派助手当前不需要重做，而是需要一轮克制、系统、低风险的 UI 打磨。

正确方向不是：

- 更炫
- 更花
- 更像网页

而是：

- 更专业
- 更统一
- 更有品牌感
- 更不打扰使用

如果按这份蓝图推进，目标不是把它变成“设计作品”，而是把它做成一个真正成熟、稳定、顺手、看起来可信的桌面产品。
